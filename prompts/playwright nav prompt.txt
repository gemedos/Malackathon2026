# Tarea módulo de navegación hasta el juego (betsson.es)

Lee primero CLAUDE.md y cúmplelo en todo momento. Esta tarea cubre SOLO la navegación desde abrir
betsson.es hasta tener el juego indicado cargado en Real Play (dinero real). La parte de visiónIA
dentro del canvas vendrá después, así que deja la arquitectura preparada para ampliarla.

## Objetivo

Que este comando

    pytest teststest_navigation.py --provider Pragmatic Play --game nombre del juego

1. construya la URL del proveedor httpswww.betsson.escasinoproveedoresprovider_slug,
2. inicie sesión con credenciales leídas de variables de entorno,
3. entre en el juego indicado en modo real (nunca demo),
4. verifique que el iframe del juego está cargado y guarde una captura como evidencia,

y que funcione igual en GitHub Actions usando GitHub Secrets.

## Stack

Python 3.12, Playwright (Chromium, API síncrona), pytest, PyYAML, python-dotenv, pydantic.
Viewport 1280x720, device_scale_factor=1, locale es-ES, timezone EuropeMadrid.

Aunque solo haya un mercado, el código no debe contener valores del mercado todo se lee del YAML.
Las variables `PROVIDER`, `GAME` y `ACCOUNT` (FUNDED  EMPTY, por defecto FUNDED) llegan por CLI o por
variables de entorno; el CLI tiene prioridad.

## URLs (`urls.py`)

- `slugify(Pragmatic Play) - pragmatic-play` minúsculas, sin tildes, espacios a guiones y sin
  caracteres especiales. Primero se consulta `provider_slugs` del YAML.
- Plan B si la URL del proveedor da 404 o redirige al lobby, ir al lobby del casino y usar el
  buscador o el filtro de proveedores. Regístralo en el log como plan B usado.

## Credenciales

- Variables `BETSSON_ES_FUNDED_USER`, `BETSSON_ES_FUNDED_PASS`, `BETSSON_ES_EMPTY_USER`,
  `BETSSON_ES_EMPTY_PASS`.
- En local se leen de `.env` con python-dotenv, solo si el archivo existe. En CI vienen de GitHub Secrets.
- `secrets.py` expone `get_credentials(account) - Credentials`, un dataclass cuyo `__repr__` y
  `__str__` muestran ``. Si falta una variable, el error dice cuál falta, nunca su valor.
- En CI, emite `add-mask` para el usuario antes de usarlo.
- Proceso en dos contextos
  1. Contexto de login sin vídeo ni traza. Las capturas usan `mask` sobre los campos de usuario y
     contraseña. Al terminar, se guarda `storage_state` en `.authes-account.json`.
  2. Contexto de trabajo nuevo, con ese `storage_state`, vídeo y traza activos desde el inicio.
- Si aparece un CAPTCHA, 2FA o verificación por email captura enmascarada, fallo con el mensaje
  Login bloqueado por verificación adicional y fin. No intentes saltarlo.

## Selectores

No conocemos el DOM de betsson.es no inventes selectores CSS frágiles.

- Todos los selectores van en `configselectorses.yaml` como listas de alternativas. Ejemplos
  botón de login [Iniciar sesión, Entrar, Acceder]; campo de usuario por label o placeholder
  [Email, Usuario, Correo electrónico]; cookies [Rechazar, Aceptar solo necesarias, Aceptar].
- Usa `get_by_role`, `get_by_label`, `get_by_placeholder` y `get_by_text`, a través de
  `find_first(candidates, timeout)`, que registra en el log qué alternativa funcionó.
- Marca cada selector no confirmado con `# TODO verificar con inspect_site.sh`.

## Flujo

1. Crear el contexto de login y abrir la URL del proveedor.
2. Gestionar el banner de cookies (preferir rechazar las no esenciales).
3. Si se pide login (modal o redirección), autenticar. Si no se pide, comprobar si hay sesión y
   forzar el login de todos modos, porque Real Play lo requiere.
4. Confirmar el login cuando sea visible el saldo o el menú de usuario, o haya desaparecido el botón
   Iniciar sesión. Guardar `storage_state`.
5. Abrir el contexto de trabajo y volver a la URL del proveedor.
6. Buscar la tarjeta del juego por nombre (texto visible, `alt` o `aria-label`), sin distinguir
   mayúsculas ni tildes. Si no está visible, hacer scroll o usar el buscador. Si hay varias
   coincidencias, elegir la exacta y registrar el resto.
7. Pasar el ratón por encima o pulsar la tarjeta, y después el botón de `real_play_labels`. Si solo
   aparece una opción de `demo_labels`, el test FALLA.
8. Esperar al iframe del juego visible, con un bounding box de tamaño razonable y estable durante 2 s.
9. Esperar a que cargue el canvas capturas del iframe cada 500 ms hasta que dos seguidas difieran
   menos de un umbral (timeout de 60 s).
10. Devolver `GameSession(page, iframe_locator, bounding_box, provider, game)` y guardar
    `artifactsesgame_loaded.png`.

## Tests y resultados

- `test_navigation.py` registra un resultado por check URL de proveedor accesible, login correcto,
  juego encontrado, Real Play lanzado e iframe cargado.
- Escribe `artifactsesnavigation_results.json` con escenario, mercado, check, estado, detalle y
  ruta de evidencia, sin credenciales.
- `test_secret_hygiene.py` recorre `artifacts` (incluido el zip de la traza descomprimido) y falla si
  encuentra el valor de cualquier variable `BETSSON_`.

## GitHub Actions (`navigation.yml`)

- Disparadores `workflow_dispatch` con inputs `provider` (por defecto Pragmatic Play) y `game`,
  más `push` a main.
- Un solo job con `MARKET es`. Las variables `BETSSON_ES_` llegan desde `secrets.`, y `PROVIDER` y
  `GAME` desde los inputs.
- Pasos checkout, setup-python 3.12, pip install, `playwright install --with-deps chromium`, pytest de
  navegación, pytest de higiene (`if always()`) y resumen en `$GITHUB_STEP_SUMMARY`.
- `upload-artifact` de `artifacts` sin `.auth`, y `rm -rf .auth` con `if always()`.
- Comentario si betsson.es bloquea las IP de GitHub, cambiar `runs-on` a `self-hosted`.
